# План: учётные записи, журнал, договоры, склад, импорт компонентов

Большой объём — делаем по этапам, каждый этап можно проверить отдельно.

## Этап 1. Вход и учётные записи
- Убрать вход через Google. Остаётся только логин + пароль, выдаваемые администратором (саморегистрации нет).
- Временный автовход под администратором (служебная учётка создаётся автоматически), экран входа пропускается. Переключатель, чтобы позже отключить.
- Настройки → «Учётные записи»: список, создание (логин, имя, пароль), удаление, сброс пароля.
- Карточка учётной записи — таблица прав: строки — разделы (Производство, Изделия, Участки, Договоры, Склад, Журнал, Настройки), столбцы — «Просмотр и редактирование», «Только просмотр». Нет галки — раздел скрыт.
- Права применяются и в интерфейсе (кнопки редактирования скрыты), и на сервере (запись запрещена).

## Этап 2. Журнал событий
- Новый раздел «Журнал»: время, пользователь, раздел, действие, объект (например «Партия П-12: Монтаж 10 → 15 шт.»).
- Фильтр по дате (по умолчанию — сегодня), пользователю, разделу.
- Записываются: изменения выполненных операций, компонентов, тех. маршрутов, партий, договоров, склада, учётных записей.

## Этап 3. Договоры и партии
- При создании партии: изделие — только выбор из списка изделий; поле «Договор» — выбор из договоров по этому изделию.
- Таблица договоров со столбцами: Шифр, Изделие, Децимальный номер, Количество, Дата поставки, Платы, ЭРИ, Монтаж ЭРИ, Детали, Сборка, Проверка, Испытания, Отгрузка, Договор/контрагент (ссылка).
- Столбцы этапов показывают прогресс привязанных партий (например «30/50»), просрочка — красным. Сопоставление этапа с операциями задаётся в изделии (у операции поле «Этап»).

## Этап 4. Состав изделия
- Типы компонентов: Сборочная единица, Деталь, ЭРИ, Материал, Стандартное изделие, Упаковка.
- У компонента: поставщик, цена, время изготовления/поставки, параметры (доп. информация), группа.
- Сборочные единицы могут содержать другие компоненты (дерево любой глубины).
- Импорт из Excel с показом требуемой структуры (A: шифр изделия, B: тип, C: наименование, D: доп. информация, E: группа, F: количество в сборочной единице) и предпросмотром перед сохранением.

## Этап 5. Склад
- Раздел «Склад» с вкладками: Доступные, Задействованные, Дефицит, Заказанные.
- При запуске партии — проверка наличия; окно со списком нехватки и кнопками «Запустить всё равно» / «Отмена».
- После запуска нужные компоненты резервируются за партией (другой цвет, недоступны другим партиям); недостающие — в «Дефицит».
- В «Дефиците» — оформление заказа (количество, ожидаемая дата) → появляется в «Заказанных».
- Флаг «Получено»: покрывает дефицит (→ Задействованные), излишек → Доступные, запись уходит из «Заказанных».

## Важное замечание
Сейчас данные хранятся в облачной базе, для работы нужен интернет. Перенос на локальный сервер без интернета — отдельная задача при развёртывании; архитектура (веб-приложение + база) это позволяет.

## Технические детали
- Таблицы: `section_permissions` (user_id, section, can_edit), `audit_log`, `stock_items`, `stock_reservations`, `stock_orders`, поле `contract_id` у партий, `stage` у операций; компоненты — дерево в JSONB изделия с `parentId`.
- Управление учётками — серверные функции с проверкой роли admin, внутри — admin-клиент (создание пользователей с подтверждённой почтой вида `login@local`).
- Журнал пишется на сервере в `saveState` (сравнение с предыдущим состоянием) и в складских функциях.
- RLS по `section_permissions` через security-definer функцию `can_edit_section`.
- Excel — библиотека `xlsx` в браузере.
- Исправить ошибку гидрации на странице входа.
