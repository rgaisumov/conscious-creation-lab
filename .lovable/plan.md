План: интерактивный трекер производственных операций

Контекст: проект на Lovable (TanStack Start + Tailwind v4). Будем строить одностраничное приложение без бэкенда — расчёты в браузере, сохранение/загрузка через JSON-файл. Цель: заменить бумажный алгоритм изготовления изделия на цифровой интерактивный граф.

Что строим

1. Главный экран — визуальный граф процесса
   - Слева: колонка «Компоненты» — карточки групп материалов/ЭРИ/оснастки/полуфабрикатов.
   - Справа: операции расположены горизонтально (Монтаж → Сборка → Проверка → Лакировка → Проверка → Испытания и т.д.).
   - Стрелки от карточек компонентов к операции, которой они нужны.
   - Стрелка от предыдущей операции к следующей, если результат предыдущего этапа идёт дальше без дополнительных компонентов.

2. Модель данных
   - Изделие: название, список операций, список компонентов.
   - Операция: id, название, ответственный, длительность, номер по порядку, массив id входных компонентов/полуфабрикатов, id выходного полуфабриката (если есть).
   - Компонент/группа: id, название, тип (материал/ЭРИ/оснастка/промизделие), массив позиций (название, количество на 1 изделие, остаток, срок поставки). У оснастки — флаг «общая/на изделие» и количество.
   - Партия: количество изделий в запуске. Все нормы расхода умножаются на неё.

3. Интерактивность и расчёты
   - При изменении остатка любой позиции или размера партии — пересчёт «сколько штук можно запустить прямо сейчас» по каждой операции.
   - Логика: для операции вычисляем лимитирующий компонент (min по остаток / норма на 1 изделие). Если у операции входной полуфабрикат от предыдущей операции — ограничиваем также количеством, которое может пройти предыдущий этап. Бутылочное горлышко подсвечивается.
   - Сверху сводка: сколько изделий можно запустить, что ограничивает, горизонт полной укомплектованности партии.

4. Режим редактирования структуры
   - Включение через переключатель «Редактирование».
   - Добавить/удалить операцию и компонент.
   - Изменить порядок операций стрелками вверх/вниз.
   - Галочками привязать компоненты к операции.
   - Указать выходной полуфабрикат операции (или «продолжение предыдущего»).
   - Редактировать название, ответственного, длительность, количество и позиции внутри карточки.

5. Сохранение и загрузка
   - Кнопки «Сохранить в файл» / «Загрузить из файла» — JSON с конфигурацией изделия.
   - Возможность быстро переключаться между несколькими изделиями через загруженные файлы (пока без бэкенда — только через файловый диалог).

6. Технические детали
   - Реализация: React-компонент в `src/routes/index.tsx` (заменить плейсхолдер).
   - Состояние: React state, никакого бэкенда.
   - Граф: SVG-оверлей поверх HTML-карточек для стрелок, позиции карточек считываем через refs/координаты.
   - Стили: Tailwind v4, семантические токены, без hardcoded цветов. Возможно — собственные компоненты Button/Input, но без сторонних библиотек для drag-and-drop (ограничиваемся формами).
   - Meta: заполнить head() для главной страницы — title, description, og.
   - Добавить sitemap.xml и robots.txt по шаблону проекта.

7. MVP и итерации
   - Первая версия: тестовые данные по примеру пользователя (Монтаж, Сборка, Проверка, Лакировка, Испытания), базовый граф, расчёт «сколько можем запустить», редактирование, сохранение/загрузка.
   - Следующие итерации: масштабирование на 20+ операций, горизонтальный скролл/зум, группировка в стадии, учёт параллельных партий, учёт ограничений по оснастке.

Риски и ограничения
- 20+ операций горизонтально потребуют скролл/зум — заложим горизонтальный overflow.
- SVG-стрелки между DOM-элементами требуют пересчёта при ресайзе — добавим обработчик resize и применяем useLayoutEffect.
- Без бэкенда нет совместного доступа и истории — только локальные файлы. Это соответствует требованию «офлайн».

Что не делаем в этой версии
- Backend / Supabase / Lovable Cloud.
- Drag-and-drop редактора графа (только формы).
- Автоматическое разбиение партии на две — это не проблема, разбиваем вручную.
- Интеграция с Excel/PDF/ERPNext.
