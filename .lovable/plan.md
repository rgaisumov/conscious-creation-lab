
# Переработка интерфейса под макет «Трекер партии»

Меняем архитектуру экрана в соответствии с загруженным дизайном и итогом переписки с ChatGPT. Бэкенд не подключаем, всё офлайн, данные в состоянии + JSON-файл.

## Что меняем в концепции

- Убираем горизонтальный граф «компоненты слева → операции справа» и длинные SVG-стрелки.
- Главный экран = **вертикальный технологический маршрут** из карточек операций сверху вниз, соединённых короткими стрелками.
- Компоненты вшиваем **внутрь карточки операции** блоком «Требуется для запуска». Отдельного столбца компонентов на графе нет.
- Полуфабрикаты по умолчанию скрыты (тумблер снизу «Показывать полуфабрикаты»).
- Стадии как отдельные сущности убираем — стадия = сама операция.
- Цвет карточек = «куда смотреть», а не «состояние»:
  - 🔴 блокирует выпуск сейчас,
  - 🟠 следующая проблема,
  - 🟡 ждёт предыдущую операцию,
  - ⚪ готова к запуску,
  - 🔵 выполняется,
  - 🟢 завершена (внимание не нужно).

## Раскладка экрана

```text
┌───────────┬────────────────────────────────────────────────────┬────────────┐
│  Sidebar  │   Верхняя статус-панель партии                     │  Подробн.  │
│  (nav)    ├────────────────────────────────────────────────────┤  выбранной │
│           │   Технологический маршрут                           │  операции  │
│           │   [операция 1] ↓ [операция 2] ↓ ... [операция N]   │            │
│           ├────────────────────────────────────────────────────┴────────────┤
│           │   Легенда + переключатели отображения + зум                     │
└───────────┴──────────────────────────────────────────────────────────────────┘
```

### Sidebar
Разделы: Обзор, Граф, Операции, Компоненты, Закупки, Отчёты, Документы, Настройки. В MVP переключение состояний экрана только для «Граф» — остальные пункты помечаем как «скоро» и оставляем заглушку.

### Верхняя панель партии
Слева блок «Ограничивают выпуск» — нумерованный список операций-блокеров с причиной. Затем плитки:
- Партия — общее количество (редактируется).
- Укомплектовано X / N — вычисляется как минимум по всем нефиктурным компонентам.
- Собрано X / N — фактически прошло операцию «Сборка» (или помеченную «ключевой»).
- Испытано X / N — прошло «Испытания».
- Отгружено X / N — вводится вручную.
- Прогноз завершения — дата + мини-график по горизонту.

### Карточка операции
Три зоны в строке:
1. Слева: иконка операции, «N. Название», ответственный, «время операции: X ч».
2. Центр: две шкалы прогресса — «Выполнено X / N» и «Можно выполнить X / N».
3. Правая часть карточки: «Требуется для запуска (k из m)» — список компонентов с цифрой «доступно/нужно» и цветной точкой статуса.
4. Крайне правая колонка: бейдж статуса («БЛОКИРУЕТ ВЫПУСК», «ОЖИДАЕТ …», «ГОТОВА»), под ним причина/дата.

Между карточками — короткая вертикальная стрелка (просто CSS-иконка, никакого SVG-оверлея).

### Правая панель «Подробности»
Показывает выбранную операцию: ответственный, время, примечание, прогресс, «Почему не можно выполнять» (карточки для каждой нехватки с кнопкой «Перейти к закупке» — заглушка), «Требуется для запуска», кнопка «Редактировать операцию».

### Нижняя полоса
Легенда цветов, чекбоксы «Показывать компоненты в карточках операций» и «Показывать полуфабрикаты», зум 100% ± и кнопка «Весь маршрут».

## Модель данных — правки

К текущим `Operation`/`ComponentGroup` добавляем:
- `Operation.completedUnits` (сколько уже выполнено),
- `Operation.note`,
- поле `Product.shippedUnits` для «Отгружено»,
- признак операции для метрик «Собрано»/«Испытано» (по id: `sborka` / `ispytaniya`).

Функции калькулятора расширяем:
- «Можно выполнить» для операции = min(входные компоненты, `completedUnits` предыдущей операции) − `completedUnits` этой операции.
- «Ограничивают выпуск» = список операций, где `можно выполнить = 0` и причина ≠ «ждёт предыдущую».
- «Укомплектовано» = min по всем расходуемым компонентам (материалы + ЭРИ + детали + материалы + упаковка), fixture не считаем.

## Тема и токены

- Оставляем текущие CSS-токены, добавляем тёмный набор под макет (глубокий сине-серый фон, панели чуть светлее, аккуратные бордеры). Светлая тема — во второй итерации, тумблер уже кладём в шапку.
- Цвета статусов: `--status-block`, `--status-next`, `--status-wait`, `--status-ready`, `--status-run`, `--status-done` в `src/styles.css`.

## Что не делаем в этой итерации

- Drag-and-drop и режим «Конструктор».
- Реальные экраны разделов Закупки/Отчёты/Документы (только заглушки).
- Управление несколькими партиями и изделиями (одно активное изделие, JSON-импорт остаётся).
- Полноценная светлая тема (переключатель есть, но применение — следующим шагом).
